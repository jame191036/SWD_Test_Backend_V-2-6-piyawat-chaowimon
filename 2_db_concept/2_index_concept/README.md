## 📌 ข้อดี และ ข้อจำกัดของ Database Indexing

**Database Indexing** คือโครงสร้างข้อมูล (เช่น B-Tree, Hash) ที่สร้างขึ้นมาคู่กับตาราง เพื่อช่วยให้ระบบฐานข้อมูลค้นหาตำแหน่งของข้อมูลได้รวดเร็วโดยไม่ต้องอ่านข้อมูลทั้งหมดทั้งตาราง (Full Table Scan) เปรียบเสมือน "ดัชนีท้ายเล่ม" ของหนังสือ

---

### 🟢 ข้อดีของ Database Indexing

1. **เพิ่มความเร็วในการค้นหาข้อมูล (Faster Query Performance):** 
   ช่วยลดเวลาในการรันคำสั่ง `SELECT` ที่มีเงื่อนไข `WHERE`, `JOIN`, หรือการค้นหาเฉพาะกลุ่มอย่างเห็นได้ชัด เปลี่ยนจากการอ่านข้อมูลแบบ $O(N)$ เป็น $O(\log N)$
2. **เพิ่มประสิทธิภาพในการจัดเรียงและการจัดกลุ่ม (Faster Sorting and Grouping):**
   ช่วยให้การประมวลผลคำสั่ง `ORDER BY`, `GROUP BY`, และ `DISTINCT` ทำงานได้เร็วขึ้นมาก เนื่องจากข้อมูลใน Index ถูกจัดเรียงไว้อยู่แล้ว
3. **ช่วยรักษาความสมบูรณ์ของข้อมูล (Data Integrity Enforcement):**
   การทำ `Unique Index` ช่วยป้องกันไม่ให้มีข้อมูลซ้ำกันในคอลัมน์นั้นๆ (เช่น Email, เลขบัตรประชาชน)
4. **ลดการทำงานของ I/O และ CPU (Lower Resource Utilization):**
   ฐานข้อมูลไม่ต้องโหลดข้อมูลทั้งตารางเข้าสู่ Memory จึงช่วยลดภาระการทำงานของ Disk I/O และ CPU ในระบบ

### 🔴 ข้อจำกัดและข้อควรระวังของ Database Indexing

1. **ส่งผลกระทบต่อความเร็วในการเขียนข้อมูล (Slower Write Operations):**
   การทำ `INSERT`, `UPDATE`, และ `DELETE` จะทำงานช้าลง เพราะทุกครั้งที่มีการเปลี่ยนแปลงข้อมูล ฐานข้อมูลจะต้องคำนวณและอัปเดตโครงสร้าง Index ตามไปด้วย
2. **สิ้นเปลืองพื้นที่จัดเก็บ (Increased Storage Space):**
   Index เป็นโครงสร้างข้อมูลที่เก็บแยกจากตัวตาราง จึงต้องใช้พื้นที่ใน Disk และ Memory (RAM) เพิ่มเติม ยิ่งตารางใหญ่หรือมี Index หลายตัว ก็ยิ่งกินพื้นที่มากขึ้น
3. **เพิ่มภาระในการดูแลระบบ (Maintenance Overhead):**
   เมื่อมีการใช้งานไปนานๆ Index อาจเกิดความกระจัดกระจาย (Index Fragmentation) ทำให้ต้องมีการ Reindex หรือ Optimize ตารางเป็นระยะ
4. **Over-indexing Risk:**
   การสร้าง Index มากเกินไปอาจส่งผลเสียมากกว่าผลดี (Write overhead สูงโดยไม่จำเป็น) และอาจทำให้ Database Query Optimizer เลือกใช้ Index ผิดตัวจนทำให้การคิวรีช้าลงได้
5. **ไม่ได้ช่วยทุก Query (Not Effective for Every Query):**
   Index อาจไม่ถูกใช้หรือไม่ช่วยให้เร็วขึ้นในบางกรณี เช่น `LIKE '%abc'` ที่ขึ้นต้นด้วย Wildcard, การครอบคอลัมน์ด้วยฟังก์ชันอย่าง `LOWER(email)` โดยไม่มี Expression Index รองรับ, Composite Index ที่ Query ไม่ได้ใช้คอลัมน์ซ้ายสุด, คอลัมน์ที่ค่าซ้ำกันมากอย่างเพศ และตารางขนาดเล็กที่อ่านทั้งตารางได้เร็วกว่า
